AI Native Coder：如何设置可信任的Agent？

背景

AI 写代码很快，但我怎么知道它写的代码是对的？如果AI每次改完都要人工跑一遍，那多开几个 Agent，只会多增加人的工作量。
如何配置让Agent的代码更可信呢？

一、让 Agent 有验证的能力

让 Agent 自己启动应用，按用户的操作走一遍，再用日志、截图或测试结果说明改动有没有生效。把功能入口和操作步骤记在 Feature Map 里，它下次就知道去哪里验证。最后让它写清楚哪些通过了、哪些失败了、哪些没跑。

排查线上问题也是一样。我之前用 ego browser 让 AI 打开 Grafana、查线上日志。后来公司运维团队出了 Skill 和工具，Agent 可以通过运维工具直接查容器云、Grafana、API Six 等系统里的信息。

二、用高质量的 Skill，让 Agent 像工程师一样工作

把自己的编码风格、排查步骤和验收习惯写成 Skill。比如发现 Agent 经常没把调用链看完就下结论，就把自己平时怎么查的步骤写进去。Lauren Tan 的开源 Cursor 插件 pstack 就是个例子。 pstack 官方仓库

Skill 写完怎么知道够不够好？
挑几个常见任务和以前做错的案例，先定通过标准，再让 Agent 实际跑一遍，看它的操作和结果。
这就是 Eval。可以让一个模型执行，另一个模型按标准看证据。需求变了就更新用例，改完 Skill 把新旧用例都跑一遍。

三、把架构改得对 Agent 更友好

把同一个功能的代码放在一起，模块边界定清楚，Agent 改一个功能就不用到处找代码。
像「不能跨模块直接引用内部实现」这种每次 review 都要提醒的事，可以写成 lint 规则，让 CI 直接拦住。

  • codebase
  • feature map
  • static analysis
  • rules / bugbot
  • style guide
